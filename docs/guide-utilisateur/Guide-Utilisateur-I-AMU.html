1. Présentation de la plateforme

I‑AMU donne aux étudiants un accès supervisé à un modèle d'intelligence artificielle, dans un cadre pédagogique maîtrisé par les enseignants.

Concrètement, I‑AMU est une application web qui se présente comme une interface de discussion (un « chat ») avec un modèle d'IA. Contrairement à un assistant grand public, l'usage est encadré : l'enseignant choisit le modèle, fixe des règles (consignes, nombre de jetons / « tokens » disponibles, documents autorisés) et peut consulter les échanges pour analyser la façon dont les étudiants utilisent l'IA.

Ce que permet I‑AMU

  • Pour l'étudiant : dialoguer avec une IA qui peut connaître le contexte d'une matière, dans un environnement balisé et équitable.
  • Pour l'enseignant : créer des matières (« ressources ») et des sessions (TD, TP, examen, étude libre), encadrer le comportement de l'IA et observer les usages.
  • Pour le chercheur : exporter des échanges à des fins de recherche, après autorisation.
  • Pour les administrateurs : gérer les comptes, les rôles, les modèles et la configuration de l'établissement.

2. Premiers pas (commun à tous)

2.1 Créer son compte

Votre rôle est déterminé automatiquement par le domaine de votre adresse e‑mail :

Domaine de l'e‑mailRôle attribué
@etu.univ-amu.frÉtudiant (automatique)
@univ-amu.frEnseignant (automatique)
Autre domaine reconnuSelon configuration (ex. chercheur)
Domaine non reconnuAucun rôle : il sera attribué par un administrateur
  1. Ouvrez la page d'inscription de I‑AMU.
  2. Saisissez votre adresse e‑mail universitaire et un mot de passe.
  3. Renseignez vos nom et prénom.
  4. Validez : un e‑mail de vérification vous est envoyé.

2.2 Vérifier son adresse e‑mail

Cliquez sur le lien reçu par e‑mail pour activer votre compte. Tant que l'adresse n'est pas vérifiée, l'accès reste restreint.

Conseil Si vous ne recevez rien, vérifiez vos spams. Le lien de vérification est à usage unique.

2.3 Rejoindre un département

À l'inscription (ou depuis votre profil), saisissez le code de département communiqué par votre établissement. Il vous rattache à votre composante (UFR, département…).

À noter Les chercheurs ne sont pas rattachés à un département : ils demandent une autorisation d'accès (voir §6).

2.4 Donner son consentement

Lors de la première connexion, vous devez accepter les conditions d'utilisation et la politique de traitement des données. La version et la date de votre consentement sont enregistrées.

2.5 Se connecter

  1. Ouvrez la page de connexion.
  2. Saisissez e‑mail et mot de passe.
  3. Vous arrivez sur votre espace (l'interface de chat pour les étudiants).

3. Rôle — Étudiant

Profil Étudiant
Vous dialoguez avec l'IA, librement ou dans le cadre d'une session de cours encadrée par un enseignant.

3.1 Discuter avec l'IA

  1. Depuis l'espace de chat, créez une nouvelle conversation.
  2. Choisissez le modèle proposé (une conversation = un modèle).
  3. Saisissez votre question dans la zone de message et envoyez.
  4. La réponse s'affiche en texte formaté (titres, listes, blocs de code coloriés).
⛶
Capture à ajouter — Interface de chat
Vue principale : liste des conversations à gauche, fil de discussion au centre, zone de saisie en bas, sélecteur de modèle.
Conseil Formulez des demandes précises et donnez du contexte. Une bonne question = une meilleure réponse.

3.2 Rejoindre une session

Un enseignant peut ouvrir une session (TD, TP, examen, étude libre) protégée par un code d'accès à 6 caractères.

  1. Cliquez sur « Rejoindre une session ».
  2. Saisissez le code à 6 caractères (ex. 4F7K2B).
  3. Vous êtes inscrit : la session impose son cadre (modèles, consignes, limites).
⛶
Capture à ajouter — Saisie du code de session
Boîte de dialogue « Rejoindre une session » avec le champ à 6 caractères.

3.3 Importer un document

Si la session l'autorise, vous pouvez joindre un fichier pour que l'IA en tienne compte. Formats possibles : PDF, Markdown (.md), texte (.txt), selon ce qu'a permis l'enseignant. Une taille maximale s'applique (jusqu'à 10 Mo).

Attention Hors session, ou si l'enseignant n'a autorisé aucun format, l'import de documents est désactivé.

3.4 Comprendre les limites

LimiteSignification
Jetons (tokens) maxVolume maximal traité par échange — au‑delà, raccourcissez votre message.
Taille d'entrée maxLongueur maximale d'un message.
Fenêtre de contexteMémoire du modèle sur la conversation en cours.

3.5 Historique & retour (feedback)

Vos conversations sont conservées puis archivées selon la durée réglée dans votre profil. Sur chaque réponse, donnez un retour (pouce haut / pouce bas) pour signaler ce qui vous a aidé.

4. Rôle — Enseignant

Profil Enseignant
Vous structurez l'usage de l'IA : vous créez des matières, ouvrez des sessions encadrées et analysez les échanges.

4.1 Gérer ses ressources (matières)

Une ressource représente une matière : code, intitulé, description, semestre. Elle passe par trois états : Brouillon, Publiée, Archivée.

  1. Ouvrez « Mes ressources » puis « Nouvelle ressource ».
  2. Renseignez code, nom, description, semestre.
  3. Ajoutez d'éventuels co‑enseignants.
  4. Publiez la ressource quand elle est prête.
⛶
Capture à ajouter — Liste / formulaire des ressources
Écran « Mes ressources » avec les états (Brouillon/Publié/Archivé) et le formulaire de création.

4.2 Créer et piloter une session

Une session est un cadre d'usage rattaché à une ressource. Choisissez son type :

TypeUsage typique
ExamenÉvaluation : cadre strict, traçabilité renforcée.
TDTravaux dirigés accompagnés.
TPTravaux pratiques.
Étude libreRévision autonome encadrée.

Cycle de vie d'une session : Brouillon → Programmée → Active → Terminée (ou Annulée).

  1. Depuis une ressource, cliquez « Nouvelle session » et choisissez le type.
  2. Définissez les dates de début et de fin.
  3. Associez le ou les modèles autorisés.
  4. Réglez les limites et consignes (§4.4).
  5. Passez la session en « Programmée » ou « Active » pour générer le code d'accès.
⛶
Capture à ajouter — Paramétrage d'une session
Formulaire de session : type, dates, modèles associés, limites de tokens, consignes, formats de fichiers autorisés.

4.3 Le code d'accès

Important Le code à 6 caractères est généré automatiquement lorsque la session passe en « Programmée » ou « Active ». Tant qu'elle est en brouillon, aucun code n'existe. Communiquez ce code aux étudiants au début de la séance.

4.4 Encadrer le comportement de l'IA

  • Consignes : instructions visibles données aux étudiants.
  • Pré‑prompt / post‑prompt : texte ajouté avant/après le message pour orienter l'IA (ton, périmètre, interdits).
  • Jetons (tokens) max et taille d'entrée : quotas par échange.
  • Documents : formats autorisés (PDF/MD/TXT) et taille maximale.
Conseil Pour un examen, utilisez le pré‑prompt pour interdire les réponses toutes faites et privilégier l'accompagnement méthodologique.

4.5 Suivre les échanges

Pour chaque session, consultez les conversations des étudiants : messages, réponses, retours (pouce haut/bas), latence et volume de jetons. Objectif : analyser comment les étudiants mobilisent l'IA.

⛶
Capture à ajouter — Tableau de suivi d'une session
Liste des étudiants inscrits et de leurs conversations, avec indicateurs (nombre d'échanges, feedback, tokens).
Cadre d'usage Le suivi sert un objectif pédagogique. Restez dans le périmètre de vos enseignements et respectez la confidentialité des étudiants.

Demander l'habilitation

Pour importer vos propres modèles, demandez l'habilitation à l'administrateur de votre département (voir §5) : depuis votre espace, soumettez une demande motivée.

5. Rôle — Enseignant habilité

Profil Enseignant habilité
Enseignant validé par l'administrateur du département, autorisé à importer des modèles d'IA personnalisés.

L'habilitation est un statut accordé par l'administrateur de département. Une fois habilité, vous conservez toutes les capacités d'un enseignant, plus la gestion de modèles.

5.1 Obtenir l'habilitation

  1. Depuis votre espace, ouvrez « Demander l'habilitation ».
  2. Expliquez votre besoin (modèle spécifique, usage pédagogique).
  3. L'administrateur approuve ou refuse ; vous êtes notifié de la décision.

5.2 Importer un modèle pour une ressource

  1. Ouvrez la ressource concernée, onglet « Modèles ».
  2. Ajoutez un modèle : nom, fournisseur, fenêtre de contexte, URL d'API, type d'adaptateur.
  3. Enregistrez : le modèle devient disponible pour cette ressource.
⛶
Capture à ajouter — Import d'un modèle sur une ressource
Formulaire d'ajout de modèle (nom, fournisseur, contexte, URL, adaptateur) au sein d'une ressource.

5.3 Partager un modèle

Un modèle rattaché à une ressource peut être partagé avec d'autres ressources du même département, pour mutualiser une configuration.

À noter Un modèle lié à une ressource ne peut pas être rendu « partageable » globalement : son partage reste cadré au département.

6. Rôle — Chercheur

Profil Chercheur
Rattaché à un laboratoire, vous demandez l'accès aux données d'un département et exportez des échanges pour vos travaux.

Le chercheur n'appartient à aucun département. Son compte est validé au niveau de l'établissement et rattaché à un laboratoire.

6.1 Demander l'accès à un département

  1. Ouvrez « Demandes d'accès » puis sélectionnez le département visé.
  2. Rédigez votre demande (objet de la recherche, données souhaitées).
  3. L'administrateur du département autorise ou rejette.
⛶
Capture à ajouter — Demande d'autorisation
Formulaire de demande d'accès à un département, avec le champ de motivation et le statut (en attente / autorisée / rejetée).

6.2 Exporter des conversations

Une fois l'autorisation accordée, vous pouvez exporter les conversations du département concerné. Chaque export est tracé (chercheur, date, adresse IP).

⛶
Capture à ajouter — Écran d'export
Liste des conversations exportables avec filtres et bouton d'export.
Données & recherche La plateforme n'anonymise pas les données : l'anonymisation et le respect du cadre éthique/RGPD relèvent de votre responsabilité de chercheur. Les utilisateurs ayant exercé leur droit d'opposition à l'usage recherche doivent être exclus de vos traitements.

9. Données personnelles & confidentialité

I‑AMU traite des données pédagogiques (conversations, retours, métriques d'usage). Voici l'essentiel à connaître :

SujetCe qu'il faut savoir
ConsentementRecueilli à la première connexion ; version et date enregistrées.
ArchivageVos conversations sont archivées selon la durée (en jours) définie dans votre profil.
Droit d'oppositionVous pouvez vous opposer à l'utilisation de vos données à des fins de recherche.
Usage rechercheLes exports par les chercheurs sont tracés (qui, quand, depuis quelle IP).
IA localeLe modèle est hébergé localement : vos échanges ne sont pas envoyés à un service tiers grand public.
Exercer vos droits Pour accéder à vos données, les rectifier ou vous opposer à un traitement, utilisez les réglages de votre profil ou contactez l'administration de votre département.

10. FAQ & résolution de problèmes

Je n'arrive pas à me connecter

Vérifiez que votre e‑mail est confirmé (lien reçu à l'inscription) et que votre compte est actif. En cas d'oubli, utilisez « mot de passe oublié ».

Mon compte n'a aucun rôle

Votre domaine e‑mail n'est pas reconnu automatiquement : un administrateur de département doit vous attribuer un rôle.

Le code de session ne fonctionne pas

Le code fait 6 caractères (lettres majuscules et chiffres). Vérifiez qu'il n'y a pas de confusion (O/0, I/1) et que la session est bien programmée ou active.

Je ne peux pas importer de document

L'import dépend de la session : l'enseignant doit avoir autorisé au moins un format (PDF/MD/TXT). Vérifiez aussi la taille (max 10 Mo).

L'IA refuse mon message ou le tronque

Vous dépassez probablement la limite de jetons ou la taille d'entrée fixée par l'enseignant. Raccourcissez votre message ou découpez‑le.

Je suis enseignant et je veux mon propre modèle

Demandez l'habilitation à l'administrateur de votre département (§5).

Je suis chercheur et je ne vois pas de données

Votre demande d'accès au département doit d'abord être autorisée par son administrateur (§6).
